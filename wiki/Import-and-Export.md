# 导入与导出

## 概览

本工具提供两个层级的导入 / 导出：

| 层级 | 内容 | 格式 | 入口 |
|---|---|---|---|
| 寄存器批量导入 | 单个从站某类区的寄存器 | JSON | 从站寄存器页 →「批量导入」 |
| 设备整树备份 | 设备 → 从站 → 寄存器整树 | `device_bundle v2.0` JSON | 设备列表页 →「管理」→ 导出 / 导入 |

## 寄存器批量导入

1. 在「从站寄存器」页点击「批量导入」，可先**下载导入模板**
2. 上传 JSON 文件，两种结构均可：
   - 包含四类区的对象：`{ "coils": [...], "holding_registers": [...] }`
   - 直接为某一区下的寄存器数组：`[ { "name": "温度", "value": 265, ... } ]`
3. 每条寄存器字段：`name`、`value`、`data_type`、`unit`、`description`
4. 导入前**预览**确认；导入会**覆盖所选类型下已有的寄存器数据**

## 设备整树备份（device_bundle v2.0）

### 导出

「管理」模式下勾选设备 →「导出选中」，得到 JSON 文件（默认文件名形如 `devices_bundle_YYYY-MM-DDTHH-mm-ss.json`）。

### 导入流程

```
选择 JSON 文件
    → 预检（只读，不落盘）
    → 界面展示：可导入 N 台 / 跳过 M 台，逐条列出动作与原因
    → 选择冲突策略并确认
    → 正式导入（单台失败只回滚该台，不影响其他设备）
    → 返回逐设备结果摘要
```

### 冲突策略

设备 ID 已存在时：

| 策略 | 行为 |
|---|---|
| `overwrite` | 覆盖原设备（运行中会先停止再覆盖） |
| `skip` | 整台跳过，原因 `device_id_exists` |
| `copy` | 分配新 ID 作为副本导入，原设备不动 |

### 导入细则

- 设备 / 从站 / 寄存器逐级判定，跳过项均给出原因码（如 `slave_id_duplicated`、`address_exists`）
- 按 `space` 预分配地址空间，再按 `address` 写入
- 导入后设备一律回到 `Created` 状态，**不自动启动**
- 旧版 v1 格式（`format: "modbus-slave-monitor.devices"`）**只读兼容**，导出端不再产出

### 格式规范

完整字段定义、模板示例与错误对照见 **[[Device-Bundle-Format|设备包格式]]**。

## 数据文件位置

- 设备配置：`%APPDATA%\com.shulink.iot.monitor\devices\{id}.json`
- 模拟配置：`%APPDATA%\com.shulink.iot.monitor\sim_config.json`

直接复制目录也可整机迁移，但跨用户交接建议使用 `device_bundle`（文件体积约为内部文件的十分之一，且不携带运行态数据）。

## 不会随备份迁移的数据

- 连接运行态（连接中 / 已连接 / 断开）、设备与从站 `status`
- 主站轮询到的实时值（寄存器 `value` 是配置初值）
- 通信日志、界面偏好（主题、语言、排版密度）
